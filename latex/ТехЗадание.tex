\section{Техническое задание}
\subsection{Основание для разработки}

Основанием для разработки является задание на выпускную квалификационную работу бакалавра «Онлайн-площадка для сдачи вещей в аренду».

\subsection{Цель и назначение разработки}

Основной задачей выпускной квалификационной работы является разработка и тестирование веб-приложения, предоставляющего возможность арендодателям публиковать объявления о сдаче вещей в аренду, а арендаторам - находить, бронировать и оплачивать такие вещи с обеспечением базовых гарантий безопасности сделки.

Задачами данной разработки являются:
\begin{itemize}
\item изучение и анализ предметной области;
\item проектирование интерфейса веб-приложения;
\item проектирование базы данных;
\item проектирование модуля взаимодействия с пользователем;
\item проектирование API веб-приложения.
\end{itemize}

\subsubsection{Регистрация}
Заинтересованные лица и их требования: пользователь желает создать учетную запись для получения доступа к функциям сервиса аренды вещей.
Предусловие: пользователь находится на странице регистрации.
Постусловие: в системе создана новая учетная запись пользователя.
\begin{enumerate}
    \item Пользователь открывает форму регистрации.
    \item Пользователь вводит имя пользователя, email, пароль и выбирает тип аккаунта.
    \item Веб-приложение передает введенные данные на сервер.
    \item Сервер проверяет корректность данных, уникальность email и длину пароля.
    \item Сервер создает учетную запись пользователя и сохраняет ее в базе данных.
    \item Веб-приложение сообщает пользователю об успешной регистрации.
\end{enumerate}
 
\subsubsection{Авторизация}
Заинтересованные лица и их требования: пользователь желает войти в систему для доступа к личному кабинету, объявлениям, бронированиям и сообщениям.
Предусловие: пользователь зарегистрирован в системе и находится на странице входа.
Постусловие: пользователь авторизован и получает доступ к функциям личного кабинета.
Основной успешный сценарий:
\begin{enumerate}
    \item Пользователь открывает форму авторизации.
    \item Пользователь вводит email или имя пользователя и пароль.
    \item Приложение передает данные авторизации на сервер.
    \item Сервер проверяет соответствие введенных данных учетной записи.
    \item Сервер подтверждает авторизацию пользователя.
    \item Веб-приложение открывает пользователю доступ к личному кабинету.
\end{enumerate}

\subsubsection{Изменение пароля пользователя}
Заинтересованные лица и их требования: пользователь желает изменить пароль для защиты своей учетной записи.

Предусловие: пользователь авторизован в системе.

Постусловие: пароль пользователя изменен, дальнейшая авторизация выполняется с новым паролем.

Основной успешный сценарий:
\begin{enumerate}
    \item Пользователь восстанавливает пароль без входа в систему, он открывает форму «Забыли пароль?».
    \item Пользователь вводит email, указанный при регистрации, и нажимает кнопку отправки кода.
    \item Приложение передает email на сервер.
    \item Сервер находит пользователя по email, генерирует шестизначный код подтверждения и сохраняет его во временном хранилище.
    \item Сервер отправляет код подтверждения на email пользователя.
    \item Пользователь вводит полученный код и новый пароль.
    \item Приложение передает email, код подтверждения и новый пароль на сервер.
    \item Сервер проверяет корректность кода и срок его действия.
    \item Сервер проверяет, что новый пароль соответствует требованиям, в частности содержит не менее 6 символов.
    \item Сервер сохраняет новый пароль пользователя и удаляет использованный код подтверждения.
    \item Приложение сбрасывает текущую сессию пользователя и предлагает войти заново с новым паролем.
\end{enumerate}
\subsubsection{Просмотр профиля пользователя}
Заинтересованные лица и их требования: пользователь желает просмотреть данные своего аккаунта и проверить заполненность профиля.

Предусловие: пользователь авторизован в системе.

Постусловие: пользователю отображаются данные его профиля.

Основной успешный сценарий:

\begin{enumerate}
    \item Пользователь открывает раздел «Профиль».
    \item Приложение отправляет запрос на сервер для получения данных текущего пользователя.
    \item Сервер находит профиль пользователя в базе данных.
    \item Сервер возвращает данные профиля: имя пользователя, email, тип аккаунта и реквизиты.
    \item Приложение отображает полученные данные пользователю.
\end{enumerate}

\subsubsection{Редактирование профиля пользователя}
Заинтересованные лица и их требования: пользователь желает изменить данные профиля с учетом типа аккаунта.

Предусловие: пользователь авторизован и открыл раздел «Профиль».

Постусловие: данные профиля обновлены, признак заполненности профиля пересчитан.

Основной успешный сценарий:
\begin{enumerate}
    \item Пользователь нажимает кнопку редактирования профиля.
    \item Пользователь изменяет необходимые поля.
    \item Для физического лица указываются ФИО, серия и номер паспорта, ИНН.
    \item Приложение передает обновленные данные на сервер.
    \item Сервер проверяет корректность и заполненность обязательных полей.
    \item Сервер сохраняет изменения в базе данных.
    \item Приложение отображает обновленный профиль пользователя.
\end{enumerate}
\subsubsection{Просмотр каталога вещей}
Заинтересованные лица и их требования: пользователь желает просмотреть список вещей, доступных для аренды.

Предусловие: пользователь открыл страницу каталога вещей.

Постусловие: на странице отображается список объявлений о вещах.

Основной успешный сценарий:
\begin{enumerate}
    \item Пользователь переходит в раздел каталога вещей.
    \item Приложение отправляет запрос на сервер для получения списка объявлений.
    \item Сервер выбирает из базы данных доступные вещи.
    \item Сервер возвращает сведения о вещах: название, описание, цену, категорию, рейтинг и изображения.
    \item Приложение отображает полученный список объявлений.
    \item Пользователь просматривает каталог и выбирает интересующую вещь.
